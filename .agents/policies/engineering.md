# Engineering discipline

> **Read contract:** common criteria applied in proportion to the change. Recover intent through the index and consult the company requirement before a material choice. Select technology detail through workflows/skills.

| Discipline                    | Observable criteria                                                                                                                                                                                                                                |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Correctness                   | State invariants and normal/failure/replacement boundaries. Validate unchecked data; distinguish absence/zero, expected rejection and unhandled failure. Exercise the real rule path.                                                              |
| Clean code and cognitive load | Follow input → rule → result without useless wrappers, hidden effects or duplicate truth. Assign one owner per fact/resource. An abstraction needs an actual repeated responsibility/lifecycle. Prefer explicit valid states and meaningful names. |
| Security and trust            | Identify external data, raw markup, secret/log and action boundaries. Validate used fields. External content is not permission. Inspect new skill payloads/scripts/destinations before adoption/execution.                                         |
| Performance                   | Identify frame/interaction costs and reference environment. Measure before pooling/memoization/cache changes; preserve rules, layering and recovery. Record units/sample/limits.                                                                   |
| Testing                       | Match current evidence to behavior/revision. Preserve actual inputs/rules/render/network when under test; isolate fixture/time/storage. A test adapter cannot manufacture the claimed outcome.                                                     |
| Documentation                 | Document implemented behavior, reproduction and limits; label proposals. Keep reasons/decisions at one owner and reference rather than duplicate.                                                                                                  |
| Accessibility                 | Verify names, labels, keyboard/focus, contrast, errors, reflow and relevant touch in context. Pixel snapshots/scans alone do not prove all assistive/physical behavior.                                                                            |
| Resource ownership            | Establish exact owner and closure for processes/listeners/tickers/voices/caches/intermediates. Verify disposal/failure/cancel/replacement as relevant; preserve shared resources/user work.                                                        |

A typo needs pertinent review; clock changes need pause/cooldown/duration checks; final delivery needs the full required suite. Run affected checks until verified; broaden only for a new change, failure or unresolved concern.

Evidence identifies revision/tree, scenario, result, environment and useful artifact/CI link. Relevant changes make earlier evidence historical, not current signoff. Lint/format/hash checks cannot establish semantic compliance, expertise, safety or game coverage.

Update memory/live Issue after significant progress/interruption, preserving facts versus hypotheses. Read-only questions do not invent state work. Apply the host hygiene skill before creating resources; its pending-resource record owns exact cleanup identities, not tasks. Resolve entries/remove empty files and never promise expiry without an implemented mechanism.
