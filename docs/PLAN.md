## Stack decisions and their consequences

**React:** manage menus, forms, dialogs and low-frequency HUD data. Its documentation reserves effects for synchronizing external systems and explains stable external-store snapshots. Here Pixi is the external system; the world state stays outside React. Mount one Pixi host through a lifecycle effect and use a cached HUD subscription. A damage notification or match submission should follow an explicit simulation event, preventing effect reruns from creating another submission. Sources: [effect guidance](https://react.dev/learn/you-might-not-need-an-effect), [external stores](https://react.dev/reference/react/useSyncExternalStore), [Strict Mode](https://react.dev/reference/react/StrictMode).

**PixiJS:** own arena rendering, ship overlays and effects. Initialization is asynchronous, the Application can own a private ticker, and Assets caches textures by URL/alias. Await setup, guard cancellation, and keep one resource owner. Load the ship atlas through a small explicit frame manifest converted from the supplied XML; do not let Pixi mistake the XML for a bitmap font. Use the supplied JSON for interface metadata where useful, respecting its logical units. Sources: [Application](https://pixijs.com/8.x/guides/components/application), [Ticker](https://pixijs.com/8.x/guides/components/ticker), [Assets](https://pixijs.com/8.x/guides/components/assets).

**Time and TypeScript:** simulate in fixed elapsed-time steps; use a seeded RNG and one active clock. The browser can suspend animation callbacks in hidden tabs, so focus/visibility pause must reset the last timestamp before explicit resume. Use strict types and discriminated states to make illegal lifecycle and result combinations visible. Source: [requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame), [strict](https://www.typescriptlang.org/tsconfig/strict.html). Version 6.0.3 is pinned because the installed typescript-eslint 8.71.0 peer range is `>=4.8.4 <6.1.0`; adopting TypeScript 7 during this deadline would exceed that supported range.

**TanStack Query and Axios:** own remote query/mutation state, not local combat. Use separate paginated keys and an explicit signal/timeout at the transport boundary. Keep one outbox as the durable source for unacknowledged results instead of persisting an entire query cache. The docs' hydration example needs a default mutation function; our chosen outbox design rehydrates serializable results and invokes the registered mutation, reducing hidden function-lifecycle dependencies. Sources: [mutations](https://tanstack.com/query/latest/docs/framework/react/guides/mutations), [QueryClient cancellation/invalidation](https://tanstack.com/query/latest/docs/framework/react/reference/classes/QueryClient), [Axios cancellation](https://axios-http.com/docs/cancellation).

**MSW:** simulate HTTP at the network boundary in development, tests and the published demo. Await worker registration before queries can run. The official browser example limits mocking to development; the challenge explicitly needs production mocks, so omit that condition. Keep shared handlers and a single mock store; parameterize latency and failures instead of intercepting component logic in tests. MSW 2.15.0 is pinned to its established `worker.start({ onUnhandledRequest })` API. Sources: [browser integration](https://mswjs.io/docs/integrations/browser), [HTTP request handlers](https://mswjs.io/docs/http/intercepting-requests).

**Playwright:** test actual navigation, keyboard actions, simultaneous touch input, collisions and network recovery. Install the controlled clock before the app creates timers. Isolate each browser context and reset game namespaces explicitly. Generate visual baselines only after reviewing the rendered states; preserve the OS/browser/viewport reference. Version 1.62.1 reuses the host's installed Chromium revision 1234. Sources: [clock](https://playwright.dev/docs/clock), [visual comparison](https://playwright.dev/docs/test-snapshots), [best practices](https://playwright.dev/docs/best-practices).

**Build and deployment:** use React + Vite and plain CSS. Browser-only combat and simulated REST resources make a static deployment sufficient. Pin dependencies and commit the lockfile. Vercel runs `npm ci` then `npm run build`, serving `dist`. Keep the service worker at the origin root with revalidation. Sources: [Vite](https://vite.dev/guide/), [Vite on Vercel](https://vercel.com/docs/frameworks/frontend/vite).

## AI slop translated into review criteria

[Merriam-Webster](https://www.merriam-webster.com/dictionary/slop) uses the term for low-quality digital content produced through AI, usually in quantity. For this project, the following are our engineering and design applications of that definition, not a published universal scoring standard.

| Failure                                                      | Why it harms this game                                                                              | Replacement and review evidence                                                                                                                                                                                 |
| ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Generic promises such as “an immersive, seamless experience” | They do not explain a control, status or decision.                                                  | Use specific text: “Time up”, “Score: 12”, “Match saved”, or “Match not saved. Try again”. Check each message in its actual state.                                                                              |
| A dashboard-like shell with decorative statistics            | It makes the next game action harder to locate.                                                     | Play is the primary menu action; options and data tabs are secondary. During combat, show health, score, remaining time, pause and controls. Review a phone screenshot at normal scale.                         |
| Invented visual style unrelated to the supplied pack         | It fragments the scene and adds asset work under a short deadline.                                  | Use the supplied naval sprites, water/sand tiles and wood/metal panels. Establish consistent spacing, type size and button states. Inspect complete screens together.                                           |
| Image-based buttons without semantics                        | A screenshot looks complete while keyboard and assistive interaction fail.                          | Build real buttons/labels/dialogs, using art as presentation. Verify Tab, Enter, Escape, focus return and accessible errors. See [W3C dialog guidance](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/). |
| A generic engine framework or wrappers hiding simple logic   | Every rule requires tracing through extra files and concepts.                                       | Keep a direct simulation update and explicit systems. A helper must remove actual duplication or own a lifecycle. Follow the path from one input to one impact and count the decisions needed.                  |
| Applying a downloaded skill by keyword                       | React/Next.js/SWR recommendations can violate this challenge's browser-only and Query requirements. | Read the relevant rule, explain its purpose, and adapt it. Use React.lazy/Vite when useful; keep TanStack Query; skip server-component advice.                                                                  |
| Passing tests that set score or hit points directly          | The evaluator has no evidence that firing and collision work.                                       | Drive inputs, advance the real clock and observe immutable state/rendered effects. Test instrumentation cannot award points or force results.                                                                   |
| A screenshot baseline update used to hide failure            | It preserves the regression as the new expected image.                                              | Inspect the actual difference and approve a changed design before replacing a baseline. Keep baselines deterministic and versioned.                                                                             |
| Claims of “60 FPS” or “100% complete” without measurements   | They conceal the remaining assessment risk.                                                         | Record environment and p95 frame intervals; mark acceptance rows only after their associated checks pass.                                                                                                       |

Use healthy, damaged and destroyed ship variants to distinguish state. Keep explosions short, hit feedback readable, low health distinguishable beyond color, and reduced-motion behavior usable. Start with the visual references in the supplied pack and review the player ship, enemy roles and island boundaries at mobile scale.
